## 요약

신청자를 **역량점수 + 정성평가** 두 축으로만 점수화하고, 소속 유형은 점수가 아닌 **쿼터(5:3:2)** 로 처리한다.
여기에 **사전학습 우선 정렬**, **기관당 인원 제한(점진적 cap)**, **동점자 구제**가 얹힌 구조다.

```
후보 로드
  → 사전 필터 (사전학습 · 자격증 · 타기수 선발자)
  → 점수 계산 (역량 50 : 정성 50)
  → 정렬 (사전학습 수료수 > 최종점수 > 역량점수 > 글자수)
  → 쿼터 계산 (중앙 5 : 지자체 3 : 공공·교육 2)
  → 라운드 cap 1 → 2 → 3 : [카테고리 충원 → 단방향 흘러내림]
  → 동점자 구제
  → 적용 (apply_selections RPC 트랜잭션 + 설정 스냅샷 저장)
```

---

## 1. 점수 산출 — 두 축뿐

최종점수는 역량점수와 정성평가 두 가지만으로 만든다.
**부처(소속 유형)는 점수에 전혀 반영되지 않고 쿼터로만 처리한다.**

```
역량점수 정규화 = 역량점수 / 역량문항 배점합              (0~1로 clamp)
정성평가 정규화 = (글자수/100 + 다수체크선택/보기수) / 2   (0~1)

최종점수 = (역량정규화 × 역량가중치 + 정성정규화 × 정성가중치) / 가중치합 × 100
```

| 항목 | 값 |
|---|---|
| 기본 가중치 | 역량 50 : 정성 50 (`DEFAULT_WEIGHTS`, UI에서 조절 가능) |
| 활용계획 만점 기준 | 공백 제거 **100자** (`PLAN_CHARS_FULL`) — 초과해도 추가 점수 없음 |
| 다수체크(U1) | 많이 고를수록 점수 상승, 보기 전체 선택 시 만점 |
| 역량 만점 | 신청 문항 중 `section='knowledge'` 문항들의 weight 합 |

## 2. 사전 필터 — 후보에서 아예 제외

정렬 전에 걸러낸다.

| 필터 | 기본값 | 동작 |
|---|---|---|
| 사전학습 미이수 제외 | 켜짐 | **전과목 수료만 통과.** 부분 수료(2과목 중 1과목)도 탈락 |
| 자격증 미보유 제외 | 켜짐 | 자격연계형 기수(C-CERT 문항 존재)에만 적용 |
| 특정 기수 선발자 제외 | 선택 | 지정한 기수에 이미 `selected` 인 신청자 제외 (중복 선발 방지) |

사전학습 수료 판정은 신청자의 **전화번호 또는 이메일**이 LMS 수료자 명단에 있는지로 확인한다.

---

## 3. 정렬 순서

```
1순위: 사전학습 수료 과목 수 (많은 순)   ← 점수보다 우선
2순위: 최종점수
3순위: 역량점수
4순위: 활용계획 글자수
```

**사전학습이 점수보다 위**라는 점이 핵심이다.
2과목 수료자는 1과목 수료 고득점자보다 무조건 앞선다.
(기수에 사전학습 과목이 없으면 `prereq_max=0` 이므로 이 정렬은 비활성)

---

## 4. 쿼터 — 5:3:2 배분과 단방향 흘러내림

신청서 **C2 문항** 응답으로 소속을 4분류한다.

| C2 응답 | 분류 | 쿼터 비율 |
|---|---|---|
| ① 중앙부처 | `central` | 5 |
| ② 광역지자체 / ③ 기초지자체 | `local` | 3 |
| ④ 공공기관 / ⑤ 교육청 | `public_edu` | 2 |
| ⑥ 그 외 | `other` | **0** (흘러내림으로만 진입) |

소수점은 나머지가 큰 쪽부터 배분한다(largest-remainder method).
예: 정원 100 → 중앙 50 / 지자체 30 / 공공 20

### 단방향 흘러내림

미달 쿼터는 **우선순위가 낮은 쪽으로만** 순차 이동한다.

```
중앙 미달 → 지자체 풀에서 충원 → 그래도 부족하면 공공 → 기타
```

아래 카테고리를 한꺼번에 섞어 점수순으로 뽑지 **않는다**.
그래서 기타 카테고리 고득점자가 지자체 지원자를 제치고 먼저 들어오는 일은 발생하지 않는다.

---

## 5. 기관 편중 방지 — 점진적 cap (핵심 장치)

한 번에 뽑지 않고 **cap을 1부터 올려가며 여러 라운드**를 돈다. 기본 상한 3명.

```
라운드 1 (cap=1): 모든 기관에 최소 1자리 보장
라운드 2 (cap=2): 남은 쿼터를 지원자 많은 기관에서 추가 충원
라운드 3 (cap=3): 상한까지 반복. 정원이 차면 조기 종료
```

이전 라운드 결과는 유지되고 **잔여 쿼터만 다음 라운드로 이월**된다.
`maxPerOrg=0`(무제한)이면 cap=∞ 로 한 라운드만 돈다.

목적: 지원자가 몰린 기관이 상위 점수를 싹쓸이하는 것을 막고 기관 다양성 확보.

### 상위부처 cap (선택)

기관명의 **첫 공백 앞**을 상위부처 키로 묶어 산하 기관 합산 인원을 제한한다.

```
"경찰청 서울특별시경찰청" → "경찰청"
"한국전력공사"            → "한국전력공사"
```

공백 없는 단독 명칭 위원회는 자동으로 안 묶이므로 `PARENT_ORG_OVERRIDES` 에 수동 매핑을 둔다.

| 기관 | 묶이는 상위부처 |
|---|---|
| 한국문화예술위원회 · 영화진흥위원회 · 영상물등급위원회 | 문화체육관광부 |
| 가축위생방역지원본부 | 농림축산식품부 |

> 매핑 케이스가 누적되면 `organizations` 테이블에 `parent_org` 컬럼을 두는 방식으로 확장 예정.

## 6. 동점자 구제

라운드 종료 후 한 번만 적용한다.
각 카테고리의 **커트라인과 아래 네 값이 모두 동일한** 미선발자를 추가 통과시킨다.

```
사전학습 수료수 | 최종점수 | 역량점수 | 활용계획 글자수
```

알고리즘이 더는 구분할 수 없는 사람을 자리 순서만으로 탈락시키지 않기 위한 형평성 장치다.
**단, 기관 cap·상위부처 cap은 동점자에게도 그대로 적용**되는 하드 리밋이다.

---

## 7. 정원과 적용

- **예비 10%**: 기본 켜짐. 정원 100명 → 실제 110명 선발.
  부동소수점 오차(`100 × 1.1 = 110.00000000000001`) 때문에 `Math.ceil` 대신 `Math.round` 사용.
- **적용**: `apply_selections` RPC가 선발·탈락을 **한 트랜잭션**으로 처리 → 중간 실패 시 자동 롤백, 중간 상태가 남지 않음.
- **스냅샷**: 적용 시점의 모든 설정이 `cohorts.selection_config` (jsonb)에 저장되어 요약 시트·결과보고서에서 선발 근거로 표시된다.

```jsonc
// selection_config 저장 항목
{
  weights, quotaRatio, maxPerOrg, excludeNoPrereq, excludeNoCert,
  totalCapacity, withReserve, effectiveCapacity,
  parentOrgCapPct, excludedCohortIds, appliedAt
}
```

## 알아둘 한계

**정성평가가 형식 지표로만 계산된다.**
글자수와 체크 개수만 보고 내용의 질은 평가하지 않는다.
→ 의미 없이 100자를 채운 사람과 충실히 작성한 사람이 같은 점수를 받는다.

**평가위원 심사가 자동선발에 반영되지 않는다.**
`evaluations` 테이블(평가위원 × 지원자)은 존재하지만 현재 선발 로직과 연결돼 있지 않다.
연결 여부는 정책 판단 필요.
